# 팅크웨어 AI Chat 사용자 화면 기능정의서

> 작성일: 2026-06-22  
> 작성 기준: 현재 `user/` 퍼블리싱 HTML/CSS/JS, `user/design-spec.md`, 이전 사용자 화면 구현 맥락  
> 적용 대상: 사용자 챗봇 화면 신규 퍼블리싱 산출물  
> 신규 산출물 위치: `user/publishing/`

---

## 1. 문서 목적

본 문서는 팅크웨어 AI Chat 사용자 화면을 새 디자인 시스템 기준으로 재퍼블리싱하기 위한 기능 기준서다.

현재 `user/` 루트에 있는 퍼블리싱 파일은 최종 디자인 기준이 아니라 기능과 화면 상태를 파악하기 위한 참조 자료로 사용한다. 실제 개발팀 전달용 산출물은 `user/publishing/html/`, `user/publishing/css/`, `user/publishing/js/`, `user/publishing/image/` 구조 아래 새로 작성한다.

---

## 2. 기준 파일

| 구분 | 파일 | 용도 |
|------|------|------|
| 기존 메인 화면 | `user/chatbot_home.html` | 홈, 채팅, 모달, AS 예약, 검색, 상태 플로우 기능 참조 |
| 기존 공통 CSS | `user/css/chatbot_home.css` | 기존 스타일과 UI 상태명 참조 |
| 기존 공통 JS | `user/js/chatbot_home.js` | 인터랙션, 플로우 전환, 상태 변경 로직 참조 |
| 로그인 필요 화면 | `user/login_required.html` | 로그인 필요 독립 상태 화면 참조 |
| 네트워크 오류 화면 | `user/network_error.html` | 네트워크 오류 독립 상태 화면 참조 |
| 예약 없음 화면 | `user/empty_reservations.html` | 예약 내역 없음 독립 상태 화면 참조 |
| 디자인 스펙 | `user/design-spec.md` | 기존 Figma 기반 수치와 화면 구성 참조 |

## 3. 신규 퍼블리싱 산출물 구조

```text
user/publishing/
├── html/
│   └── *.html
├── css/
│   └── *.css
├── js/
│   └── *.js
└── image/
    └── *.{png,jpg,svg}
```

### 작성 원칙

- 신규 화면은 기존 파일을 복사해 수정하지 않고 새 디자인 시스템 기준으로 새로 작성한다.
- 기존 파일은 기능, 문구, 상태, 인터랙션 흐름을 확인하는 용도로만 사용한다.
- 개발팀 전달을 고려해 HTML 주석, 의미 있는 class, `data-*` 속성을 충분히 사용한다.
- 스타일 전용 class와 JS 동작용 selector는 가능한 분리한다.
- 모든 클릭 요소는 더미 동작이라도 화면 전환, 모달 열기/닫기, 선택 상태 변경 등 확인 가능한 반응을 제공한다.
- 실제 개인정보처럼 보이는 샘플 값은 사용하지 않는다.

## 18. 개발팀 전달용 마크업 원칙

- 각 화면 최상단에 화면명, 목적, 관련 기능 ID 주석을 작성한다.
- 반복 목록은 시작/끝 주석을 두고, 실제 데이터 치환 지점을 명확히 표시한다.
- JS가 참조하는 요소에는 `data-js`, `data-action`, `data-flow-target`, `data-state` 같은 명확한 속성을 사용한다.
- 화면 상태는 `is-open`, `is-active`, `is-selected`, `is-disabled`, `is-loading`, `is-complete`처럼 일관된 상태 class로 표현한다.
- 더미 데이터는 실제 개인정보처럼 보이지 않게 작성하고, 실제 연동 예정 값은 `<!-- TODO: API value -->` 형태로 표시한다.
- 링크/버튼은 실제 기능 연동 전이라도 `type="button"`과 명확한 `aria-label`을 제공한다.
- 개발팀이 컴포넌트화하기 쉽도록 큰 화면을 header, main, footer, modal, flow, card, list 단위로 나눈다.
